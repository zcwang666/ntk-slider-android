## v1.10.0：定时器改为「本地即时回显 + 开启时对齐」

### 问题

v1.9.0 的「预览定时」按钮是**错的**，已撤掉。

原因：真机实测证明，**定时器停止时设备根本不回传真实设定值**——
按 3 次「秒＋」发出 3 条 `E4B6`，C6 依然是旧值（57）纹丝不动。
所以"向设备查询"查回来的永远是旧值，点完看起来像没反应，反而误导。

### 现在的做法

1. **App 自己记住你调的时/分/秒**，按 ±、输数字都**立刻回显**，不再等设备
2. **60 秒自动进位**（57 秒再按 5 下 → `00:01:02`），
   进位时下发的是**增量指令**（`1×分+` 配 `59×秒−`），不是从设备值重算，避免重复发送
3. **点「开启定时器」时清掉本地草稿**，文本框自动切到设备上报的真实值——
   因为设备正是从这一刻起才开始回传真实时长

### 真机验证

| 操作 | 结果 |
|---|---|
| 连点 5 次「秒＋」 | `00:00:57 → 00:01:02`，指令 `2×A1 + 1×A2 + 59×B1 + 2×A1` ✅ |
| 点「开启定时器」 | 文本框切到 `00:00:52`（设备实际值），F4=1 ✅ |
| 点「关闭定时器」 | F4=0 ✅ |

## v1.8.0：修复「连接后再扫描会卡死」

### 问题

连上滑轨后再进设备页点「开始扫描」，会出现扫描不到设备、滑轨掉线、
之后既退不出去也连不上，只能杀进程重启。

### 原因

`startScan()` 在已连接时会把状态从 `READY` 直接覆盖成 `SCANNING`，
**但 GATT 连接根本没关**。于是 App 一边握着连接一边扫描——
真机上这两件事会互相干扰，滑轨被踢下线；
掉线后自动重连又和扫描抢设备，状态机就此锁死。

### 修复

1. **扫描与连接互斥**：已连接时禁止启动扫描，`startScan()` 里加了硬护栏
2. **UI 层禁用**：已连接时「开始扫描」不可点，并提示原因
3. **新增「复位链路」**：一键清干净扫描/连接/重连状态，
   卡死时不用再杀进程（真机验证：复位后立即可以正常扫描）

### 真机验证

| 场景 | 结果 |
|---|---|
| 已连接时点「开始扫描」 | 不启动扫描，**链路完好**（遥测继续上报） |
| 点「复位链路」 | 日志「链路已复位」，状态回到未连接 |
| 复位后再扫描 | 正常找到 `AC:E6:70:00:12:9F` |
| 返回键 | 正常回首页 |

### 其他

- 定时器里的 `A1/B1`、`A2/B2`、`A3/B3` 字样已删除（只保留 时/分/秒）
- 相片卡新增设备下限提示（见下）

## v1.7.0：定时器改成闹钟式输入

### 定时器（视频模式底部）

时 / 分 / 秒 三列，每列**上＋、中间可输入、下−**：

```
   时        分        秒
   ＋        ＋        ＋        ← A3 / A2 / A1
 [ 00 ]   [ 00 ]   [ 19 ]       ← 可直接输入
   −        −        −         ← B3 / B2 / B1
```

档位对应关系由**官方函数名**确认：`timer01 / timer11`、`timer02 / timer12`、`timer03 / timer13`
——第一位 0=减 / 1=加，第二位 1=秒 / 2=分 / 3=时。

输入一个时/分/秒后，App 按当前上报值算出差值，逐单位补齐 ± 指令。

### 设置页精简

「相片设置」和「定时器」从 **设置** 页移除（首页已经有了），现在设置页只剩：
**运动参数 · 行程与型号 · 设备维护**。

### 目标张数的设备下限是 20

实测（型号标定 32）：

| 操作 | 发出的指令 | 目标张数 |
|---|---|---|
| 从 30 连按 18 次 − | 18 × `D2B6` 全部发出 | 停在 **20** |
| 输入框输入 15 | 5 × `D2B6` 发出 | 仍是 **20** |
| 输入框输入 50 | 3 × `D3B6` | **50** |

**App 每次都如实下发指令，是设备固件在 20 处拒绝下调。**
官方小程序对此没有任何边界判断（六个纯发送函数），所以用官方也一样。
现在界面上会直接标出「已达设备下限（20 张）」。

### 修复：Material3 OutlinedTextField 撑爆布局

三个 `OutlinedTextField` 并排时，Material3 的 `defaultMinSize(minWidth = 280dp)` 让每个
输入框至少要求 280dp 宽，三个挤进 383dp 的行里直接导致整个页面布局异常
（状态条、右上角图标全部变成零尺寸，点击失效）。已改用 `BasicTextField` + 自绘边框。

## v1.5.0：真机实测后的修复与修正

### 修复：返回栏点不动

`BackHeader` 的手势 key 用了 lambda，每次重组都会重建手势处理器；
真机上页面每秒都在刷新遥测，触摸期间一重组这次点击就被取消，所以**点返回没反应**。
已改为固定 key + `rememberUpdatedState`。同类写法（状态条图标、参数菜单行）一并修掉。

### 修正：速度键只在视频模式下生效

真机实测对照：

| 模式 | 操作 | 结果 |
|---|---|---|
| 视频（D0=1） | 5 × 速度＋ | D1 `4401 → 5502`（44.0% → 55.0%）**✅ 生效** |
| 延时（D0=2） | 10 × 速度＋ | D1 纹丝不动 **❌ 无效** |

所以速度键现在**只在视频模式下可用**；切到其它模式会变灰并提示
「速度调整仅在视频模式下生效（当前为延时模式）」。

### 确认：照片张数预置

| 档位 | 实测 |
|---|---|
| +10（A2） | 点 3 次 → 目标张数 `200 → 230`，**每次正好 +10** ✅ |

`A1/A2/A3 = +1/+10/+100`、`B1/B2/B3 = −1/−10/−100` 的对应关系成立。

## v1.3.0 的改动

### 1. 发现了真正的调速指令（重要）

原以为协议不支持调速，真机实测**推翻了这个结论**：

```
基线          D1 = 1549  → 速度 15.49%
按 3 次调速键  → 下发 3 × A55A04B2B6AA
查询          D1 = 1694  → 速度 16.94%   ✅
```

也就是说 **`B2B6` / `B8BC` 在这台滑轨上就是调速**（每次约 ±0.5%）。
官方小程序把它们标成「上升 / 下降」，是因为别的机型带垂直轴。
本版已把它们正名为 **「速度 −」/「速度 ＋」**。

### 2. 启动与停止合并成一个键

同一个圆形按钮：停止时显示 ▶（启动），运行时显示 ■（停止）。
因为按下的瞬间会先翻转本地意图再发指令，所以不会再出现"启动后按不动"。

### 3. 结构调整

- 工作模式移到底部常驻条，拇指够得着
- 设置、设备移到主页右上角
- 位置改为只显示进度条（不再显示具体毫米数）
- 启动/停止合并；「上升/下降」正名为速度 ±

### 4. 移除了打点与场景

- **AB 打点**：它依赖「行程标定」指令做闭环移动，而那条指令会改写滑轨行程，副作用太大，已整体移除
- **场景预设**：一并移除

### 5. 「行程标定」开关保留并加了警示

方向控制（左移/右移）**必须先打开它**，否则设备不响应任何方向指令。
但请注意：**这个模式会让移动改写滑轨的行程端点**，所以文案已明确标注：

> 已开启 · 此模式下移动会重新定义行程端点

开关状态以**设备回报的 F2** 为准，不再出现"界面显示已关、设备其实还开着"的不同步。

## 首次使用

1. 滑轨上电，确认控制器蓝牙指示灯在闪。
2. App 启动 → 右上角 **ⓘ 设备** → 授权「附近的设备」权限 → 开启蓝牙 → **开始扫描**。
3. 列表出现 `NTK-1` → **连接**。连接后自动拉取全部状态。
4. 右上角 **⚙ 设置** 进入参数；右上角 **⟳** 重新拉取状态。

## 排查

- 连不上：确认滑轨已上电、距离 3 米内、蓝牙已开。
- 方向键没反应：先打开「行程标定」开关。
- 想知道发生了什么：「设备」页的 **链路日志** 逐条列出收发的指令字节。
- 想探测未知指令：「设备」页 **原始指令** 卡片可直接下发任意 6 字节帧。
